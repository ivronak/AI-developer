# PRD – AI प्रोजेक्ट मैनेजमेंट डैशबोर्ड

12 अक्टूबर 2026 · Sohil

## 1. सारांश

एक मोबाइल-फ़्रेंडली वेब डैशबोर्ड, जिससे नॉन-टेक्निकल मालिक लगभग 50 क्लाइंट प्रोजेक्ट के रोज़ के चेंज Claude API से beta में करवाए, क्लाइंट से approve कराए और एक बटन से live करे — बिना डेवलपर के।

**समस्या:** कोड अलग-अलग डेवलपर्स के GitHub में बिखरा है; छोटा चेंज 3-4 दिन लेता है; टीम पर पूरी निर्भरता है।

**लक्ष्य:** पूरा कंट्रोल मालिक के पास, हर चेंज सुरक्षित रास्ते (beta → approval → live) से, और ग़लती हो तो मिनटों में वापसी।

**सफलता के पैमाने**

| पैमाना | आज | लक्ष्य (6 महीने) |
| --- | --- | --- |
| छोटे चेंज का समय | 3-4 दिन | 1 दिन से कम |
| डेवलपर की ज़रूरत | रोज़ | महीने में 1 बार या कम |
| फ़ुल-टाइम डेवलपर | 10-12 | 0 (सिर्फ़ on-call) |
| live पर बिना approval गया चेंज | पता नहीं | 0 |
| साइट वापस चालू करने का समय | घंटे | 15 मिनट से कम |
| API ख़र्च प्रति active प्रोजेक्ट | — | ₹12,000/महीना से कम |

**मूल दस्तावेज़:** यह PRD "AI-संचालित प्रोजेक्ट मैनेजमेंट सिस्टम – Requirement Document" (फ़ाइल: AI-Project-Management-Requirement.md) पर आधारित है; वहाँ "क्यों" है, यहाँ "क्या बनाना है"।

## 2. यूज़र और भूमिकाएँ

तीन भूमिकाएँ; सारे अधिकार role से तय होंगे, किसी इंसान से नहीं।

| भूमिका | कौन | मुख्य ज़रूरत | अधिकार |
| --- | --- | --- | --- |
| Owner | कंपनी मालिक (नॉन-टेक्निकल) | मोबाइल से कभी भी चेंज करवाना, live करना, सब देखना | सब कुछ; Go Live, Restore, यूज़र जोड़ना-हटाना, API key |
| Developer | बची टीम या on-call एक्सपर्ट | अटके केस में मदद, समीक्षा | सिर्फ़ असाइन किए प्रोजेक्ट; beta में चेंज; Go Live सिर्फ़ Owner की अनुमति से |
| Client | प्रोजेक्ट का ग्राहक | अपना चेंज beta में देखना और हाँ/ना कहना | सिर्फ़ अपना approval पेज (लॉगिन नहीं, एक बार का सुरक्षित लिंक) |

**मुख्य यूज़र स्टोरी (Owner)**

- रात 11 बजे क्लाइंट का WhatsApp आता है; मैं मोबाइल पर स्क्रीनशॉट डालकर चेंज लिखता हूँ, Claude beta में करता है, मैं क्लाइंट को लिंक भेजता हूँ।
- सुबह क्लाइंट approve करता है; मैं OTP डालकर Go Live दबाता हूँ।
- live में error आए तो मुझे अलर्ट मिलता है, मैं एक बटन से rollback करता हूँ।

## 3. दायरा

v1 का मक़सद सिर्फ़ इतना है कि 1-2 पायलट प्रोजेक्ट पर रोज़ का चेंज बिना डेवलपर beta से live तक पहुँचे; बाक़ी सब बाद के version में।

**v1 में शामिल**

- लॉगिन, OTP, तीन role, activity log
- प्रोजेक्ट लिस्ट और स्टेटस (GitHub से अपने-आप)
- प्रोजेक्ट चैटबॉट (Claude API) — टेक्स्ट और स्क्रीनशॉट
- Live से Beta sync, beta deploy, tests चलाना
- क्लाइंट approval लिंक
- Snapshot + Go Live, Rollback
- रोज़ का DB बैकअप, Restore बटन
- मैसेज स्विच (बंद / टेस्ट-नंबर / चालू) और पेमेंट टेस्ट मोड
- मोबाइल अलर्ट (साइट डाउन, error, बैकअप फ़ेल)

**v2 और v3 में (पूरी सूची सेक्शन 4 और 5 में)**

- वीडियो/ऑडियो इनपुट
- नया प्रोजेक्ट फ़ॉर्म, Project Clone, SaaS conversion
- Flutter Build & Submit बटन
- cPanel प्रोजेक्ट का पूरा ऑटो-deploy (v1 में सिर्फ़ VPS)
- API ख़र्च का प्रोजेक्ट-वार रिपोर्ट

## 5. स्क्रीन और यूज़र स्टोरी

कुल 16 स्क्रीन (v1 में 8, बाद में 8); हर स्क्रीन पहले मोबाइल के लिए डिज़ाइन हो, फिर डेस्कटॉप पर फैले।

**S1. लॉगिन**

- ईमेल/मोबाइल + पासवर्ड, फिर OTP।
- 5 ग़लत कोशिश पर 15 मिनट लॉक, Owner को अलर्ट।

**S2. होम — प्रोजेक्ट लिस्ट**

- हर प्रोजेक्ट का कार्ड: नाम, क्लाइंट, टेक (Laravel/Flutter/Flask), स्टेटस रंग, आख़िरी deploy, आख़िरी बैकअप, खुले चेंज की गिनती।
- ऊपर फ़िल्टर: सब / लाल / approval बाक़ी / active।
- सर्च बॉक्स।

**S3. प्रोजेक्ट डिटेल**

- टैब: चैट · चेंज · Deploy · बैकअप · सेटिंग।
- ऊपर बटन पट्टी: Live से Beta sync · Beta deploy · Go Live · Rollback।
- beta और live के लिंक, दोनों पर कौन-सा commit चल रहा है।

**S4. प्रोजेक्ट चैटबॉट**

- चैट बॉक्स + स्क्रीनशॉट अपलोड।
- हर चेंज रिक्वेस्ट एक नया "चेंज" बनाता है (स्टेटस: नया → beta में → टेस्ट पास → क्लाइंट के पास → approved → live)।
- Claude क्या बदल रहा है, कौन-सी फ़ाइलें — सादी भाषा में सारांश; tests का नतीजा।
- "क्लाइंट को भेजो" बटन → S5 का लिंक बने, WhatsApp/ईमेल पर शेयर।

**S5. क्लाइंट approval पेज (बिना लॉगिन)**

- चेंज का सादा विवरण, "क्या-क्या जाँचना है" सूची, beta लिंक।
- Approve / बदलाव चाहिए (टिप्पणी + स्क्रीनशॉट)।
- लिंक 7 दिन में या एक बार जवाब के बाद बंद; हर जवाब activity log में।

**S6. Go Live / Rollback पुष्टि**

- क्या जा रहा है उसका सारांश, आख़िरी snapshot का समय।
- OTP डालकर पुष्टि; Go Live के बाद 15 मिनट तक ख़ास मॉनिटरिंग।

**S7. बैकअप**

- तारीख़-वार सूची (DB, फ़ाइलें, snapshot), आकार, सफल/फ़ेल।
- "अभी बैकअप लें" और "Restore to beta / live" (live पर OTP)।

**S8. यूज़र और लॉग (सिर्फ़ Owner)**

- यूज़र जोड़ना, role देना, प्रोजेक्ट असाइन करना, एक बटन से एक्सेस बंद।
- activity log: फ़िल्टर यूज़र / प्रोजेक्ट / तारीख़ से।

**बाद के version की स्क्रीन (v2, v3)**

**S9. Debug live error (v2)**

- live का error log दिखे; "Claude से जँचवाओ" बटन।
- Claude कारण सादी भाषा में बताए और फ़िक्स beta में बनाए; आगे सामान्य फ़्लो (tests → approval → Go Live)।

**S10. नया प्रोजेक्ट (v2)**

- फ़ॉर्म: नाम, क्लाइंट, टेक स्टैक, requirement (.md अपलोड), डोमेन, सर्वर (VPS/cPanel), डेटाबेस।
- सबमिट पर: GitHub रिपॉज़िटरी, beta और live environment, ब्रांच, खाली DB अपने-आप।
- DNS और SSL के लिए चेकलिस्ट या एक बटन वाली स्क्रिप्ट।
- असली कोड Claude Code (सब्सक्रिप्शन) में बने; GitHub में push होते ही प्रोजेक्ट डैशबोर्ड पर दिखे।

**S11. API ख़र्च (v2)**

- प्रोजेक्ट-वार और महीने-वार Claude API ख़र्च, हर चेंज का ख़र्च।
- हर प्रोजेक्ट की मासिक सीमा; 80% पर अलर्ट, 100% पर Owner की अनुमति के बिना नया AI काम नहीं।

**S12. अस्थायी एक्सेस (v2)**

- Owner किसी एक्सपर्ट को एक प्रोजेक्ट का एक्सेस 2 / 8 / 24 घंटे के लिए दे; समय पूरा होते ही अपने-आप बंद।
- उस दौरान का सारा काम activity log में अलग से चिह्नित।

**S13. Project Description और Clone (v3)**

- "Description बनाओ" बटन: Claude कोड, DB टेबल स्ट्रक्चर और फ़्लो पढ़कर पूरा requirement document (.md) बनाए।
- डाउनलोड पर OTP; हर डाउनलोड activity log में।
- "Clone" बटन: उसी description से नया प्रोजेक्ट (S10 का फ़ॉर्म पहले से भरा); सिर्फ़ लोगो, नाम, नंबर, रंग, डोमेन बदलें। पुराना प्रोजेक्ट अछूता।

**S14. SaaS conversion (v3)**

- Clone से एक अलग नया SaaS प्रोजेक्ट; पुराना प्रोजेक्ट नहीं छुआ जाएगा।
- चरण दिखें: multi-tenant design → beta में बनाना → पुराने क्लाइंट डेटा का merge टेस्ट → एक्सपर्ट समीक्षा → Go Live।
- "एक्सपर्ट समीक्षा" चरण पूरा हुए बिना Go Live बटन बंद।

**S15. Flutter release (v3)**

- "Release तैयार" सूची: पिछले release के बाद के ऐप चेंज।
- Build & Submit: पहले internal / TestFlight, फिर production; स्टोर review का स्टेटस दिखे।
- अगर API बदला है तो चेतावनी: "पुराना ऐप टूट सकता है" — backward compatibility जाँच पास होने पर ही backend live।
- force-update संदेश का on/off और न्यूनतम version।

**S16. वीडियो / ऑडियो इनपुट (v3)**

- चैट में ऑडियो रिकॉर्ड करें → टेक्स्ट बने → Claude को जाए।
- वीडियो अपलोड → मुख्य फ़्रेम निकलें → स्क्रीनशॉट की तरह Claude को जाएँ।

## 6. सिस्टम ढाँचा

डैशबोर्ड अकेला नियंत्रण-केंद्र है: यूज़र सिर्फ़ उससे बात करते हैं, और वह पाँच सेवाओं को चलाता है। Claude सिर्फ़ beta छूता है, live सिर्फ़ बटन से।

```
   Owner                 Developer               Client
(मोबाइल/कंप्यूटर)     (सिर्फ़ असाइन प्रोजेक्ट)    (सिर्फ़ approval लिंक)
      │                      │                       │
      ▼                      ▼                       ▼
┌──────────────────────────────────────────────────────────────┐
│              डैशबोर्ड (Laravel, अलग VPS)                       │
│   चेंज · approval · deploy · rollback · बैकअप · यूज़र + log     │
└──────────────────────────────────────────────────────────────┘
      │            │             │              │            ▲
      ▼            ▼             ▼              ▼            │
 Claude API   कंपनी GitHub     सर्वर        Cloud storage    मॉनिटर
 (beta में    (कोड, ब्रांच)  (beta + live)  (रोज़ बैकअप)   (अलर्ट भेजे)
  चेंज)
```

चेंज का रास्ता: डैशबोर्ड Claude API से beta ब्रांच में कोड बदलवाता है, GitHub में commit करता है, और सर्वर पर SSH से deploy करता है। मॉनिटर उल्टी दिशा में चलता है — साइट डाउन हो तो वह डैशबोर्ड को सूचना भेजता है।

| जुड़ाव | कैसे | किस काम के लिए |
| --- | --- | --- |
| Claude API | API key (सिर्फ़ Owner के पास) | कोड पढ़ना-बदलना, सारांश, debug |
| GitHub | GitHub App / token, org स्तर पर | रिपॉज़िटरी सूची, ब्रांच, commit, merge |
| सर्वर | SSH key | deploy, migration, DB sync, snapshot, log पढ़ना |
| Cloud storage | S3-compatible key | बैकअप रखना और वापस लाना |
| मॉनिटर + अलर्ट | uptime जाँच + Telegram/ईमेल | डाउन, error, बैकअप फ़ेल की सूचना |

## 7. डेटा मॉडल

डैशबोर्ड का अपना डेटाबेस सिर्फ़ प्रबंधन का रिकॉर्ड रखेगा; प्रोजेक्ट का कोड GitHub में और प्रोजेक्ट का डेटा उसके अपने सर्वर पर रहेगा।

| टेबल | मुख्य फ़ील्ड | किससे जुड़ी |
| --- | --- | --- |
| users | name, email, mobile, role, otp_secret, is_active | projects (असाइनमेंट) |
| projects | name, client_name, tech_stack, github_repo, host_type (VPS/cPanel), status_color | environments, changes |
| environments | project_id, type (beta/live), url, server, deploy_path, db_name, current_commit, message_mode, payment_mode | projects |
| changes | project_id, title, requested_by, status, ai_summary, branch, test_result | projects, approvals, deployments |
| change_attachments | change_id, type (image/audio/video), file_url | changes |
| approvals | change_id, token, expires_at, decision, client_comment | changes |
| deployments | project_id, environment_id, change_id, commit, snapshot_id, by_user, result, rolled_back | environments, backups |
| backups | project_id, type (db/files/snapshot), storage_url, size, status, created_at | projects |
| alerts | project_id, type, message, seen_at | projects |
| activity_logs | user_id, project_id, action, prompt_text, details, ip, created_at | users, projects |
| ai_usage | project_id, change_id, input_tokens, output_tokens, cost | projects (F18 के लिए) |

**गोपनीय डेटा:** सर्वर पासवर्ड, SSH key, API key — डेटाबेस में encrypted, स्क्रीन पर कभी पूरा न दिखें।

## 8. Non-functional ज़रूरतें

सबसे ऊपर सुरक्षा और कम ख़र्च; डैशबोर्ड ख़ुद भी उतना ही सुरक्षित हो जितने प्रोजेक्ट, क्योंकि उसके पास सबकी चाबी है।

| क्षेत्र | ज़रूरत |
| --- | --- |
| सिक्योरिटी | HTTPS, OTP हर लॉगिन पर, गोपनीय डेटा encrypted, Go Live/Restore/Delete पर दोबारा OTP, Cloudflare के पीछे |
| live की सुरक्षा | Claude कभी सीधे live ब्रांच या live DB पर नहीं लिखेगा; live सिर्फ़ Go Live बटन से |
| मोबाइल | 360px चौड़ी स्क्रीन पर पूरा काम; बड़े बटन; धीमे नेटवर्क पर भी चले |
| ख़र्च | Claude API की प्रोजेक्ट-वार मासिक सीमा; सीमा का 80% पार होने पर अलर्ट; बड़े काम Claude Code (सब्सक्रिप्शन) पर |
| रिकवरी | Rollback 5 मिनट के अंदर; डैशबोर्ड का अपना DB भी रोज़ बैकअप |
| लॉग | हर क्रिया activity log में, कम से कम 1 साल तक |
| उपलब्धता | डैशबोर्ड बंद हो तब भी प्रोजेक्ट चलते रहें (डैशबोर्ड सिर्फ़ नियंत्रण है, बीच का रास्ता नहीं) |
| भाषा | इंटरफ़ेस हिंदी + अंग्रेज़ी; Claude के सारांश सादी हिंदी में |

**नियम:** Claude subscription को डैशबोर्ड के पीछे नहीं जोड़ा जाएगा; डैशबोर्ड सिर्फ़ Claude API key से चलेगा।

## 9. v1 की स्वीकृति-शर्तें

v1 तभी पूरा माना जाएगा जब पायलट प्रोजेक्ट पर ये सारी जाँचें मालिक ख़ुद, मोबाइल से, बिना डेवलपर के पास कर दे।

- [ ] OTP के बिना लॉगिन नहीं होता; Developer को बिना असाइन प्रोजेक्ट नहीं दिखता।
- [ ] GitHub org में नई रिपॉज़िटरी डालते ही 5 मिनट में प्रोजेक्ट लिस्ट में आ जाती है।
- [ ] Live से Beta sync के बाद beta में live का ताज़ा रिकॉर्ड दिखता है।
- [ ] beta में मैसेज स्विच "बंद" होने पर एक भी SMS/WhatsApp/ईमेल बाहर नहीं जाता; "टेस्ट-नंबर" पर सिर्फ़ तय नंबर पर जाता है।
- [ ] स्क्रीनशॉट के साथ लिखा असली क्लाइंट चेंज Claude beta में करता है और tests का नतीजा दिखता है।
- [ ] क्लाइंट बिना लॉगिन लिंक से Approve करता है, और वह activity log में दर्ज होता है।
- [ ] बिना approval के Go Live बटन काम नहीं करता (Owner override सिर्फ़ कारण लिखकर)।
- [ ] Go Live से पहले snapshot बनता है; Rollback 5 मिनट में पिछली हालत लौटा देता है।
- [ ] रोज़ का बैकअप cloud storage में दिखता है, और beta पर Restore सफल होता है।
- [ ] साइट बंद करने पर 5 मिनट में मोबाइल पर अलर्ट आता है।
- [ ] एक महीने का Claude API ख़र्च दर्ज होता है और देखा जा सकता है।

## 10. Release योजना और ट्रैकिंग

काम चार हिस्सों में होगा; हर हिस्से का गेट पार होने पर ही अगला शुरू, और उसी हिसाब से डेवलपर घटें।

| चरण | समय | क्या बनेगा (फ़ीचर ID) | आगे बढ़ने का गेट | स्टेटस |
| --- | --- | --- | --- | --- |
| तैयारी | महीना 1 | कंपनी GitHub org, सारे प्रोजेक्ट उसमें, एक्सेस सूची, पायलट चुनना (डैशबोर्ड के बाहर का काम) | सारा कोड और एक्सेस मालिक के पास | बाक़ी |
| v1 | महीना 2-3 | F01-F15, 1-2 पायलट प्रोजेक्ट पर | सेक्शन 9 की सारी जाँचें पास; एक महीने का API बिल ठीक | बाक़ी |
| v2 | महीना 3-4 | F16-F21, सारे active प्रोजेक्ट जोड़ना; डेवलपर 12 से 5 | एक महीना डेवलपर की मदद लगभग शून्य | बाक़ी |
| v3 | महीना 4-6 | F22-F27, dormant प्रोजेक्ट भी; फ़ुल-टाइम डेवलपर शून्य | — | बाक़ी |

**रिकॉर्ड कैसे रखें**

- हर फ़ीचर का स्टेटस सेक्शन 4 की टेबल में बदलते रहें: बाक़ी → चल रहा है → टेस्ट में → पूरा।
- किसी फ़ीचर पर फ़ैसला बदले तो उसी पंक्ति के आगे कारण लिखें, ताकि रिकॉर्ड रहे।
- हर चरण पूरा होने पर ऊपर की टेबल का स्टेटस "पूरा" करें।

**Claude Code को क्या देना है:** यह PRD और "Requirement Document" — दोनों की .md फ़ाइल नए प्रोजेक्ट की रिपॉज़िटरी में `docs/` फ़ोल्डर में रखें, और Claude Code से कहें: "docs पढ़ो और v1 (F01-F15) बनाना शुरू करो"।
